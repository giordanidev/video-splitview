# Architecture, limitations and packaging

Video Splitview is **100% Flutter** using the **libmpv** engine (via `media_kit`).
The UI and every video are composed in the **same Flutter scene**: there are no
overlapping native layers. This is what makes the wipe, blink and multi-cell
layouts plain Flutter widgets instead of native surface tricks.

## 1. Known limitation (important)

On Windows, `media_kit` renders through ANGLE and **does not use zero-copy
hardware decoding** — it falls back to **copy-back** (`*-copy`). Consequences:

- The UI exposes `off` / `compat`; `direct` maps to `auto-copy`.
- With **2×4K at the same time**, expect higher CPU/RAM/GPU usage (order of
  magnitude: **+10–20% of one core and +150–300 MB per 4K**).
- Mitigation to measure with real files: lower the render resolution per player
  (`VideoControllerConfiguration.scale`/`width`/`height`), since in split view each
  video occupies roughly a fraction of the window.
- Upstream: `media_kit` is waiting on mpv's offscreen D3D11 renderer to enable
  zero-copy.

## 2. Structure

```
lib/
  main.dart              entry (window, media_kit, ProviderScope)
  frontend/              presentation
    app.dart             MaterialApp (theme + locale)
    theme/               design tokens + theme
    widgets/             topbar, stage, controls, modals, flags, tooltips
  backend/               domain logic (no UI)
    models/              types (Side a–d, SplitLayout, PlayerState, Settings, enums)
    services/            mpv_side, playback_bridge (sync), file picker, capture, update
    state/               Riverpod (providers, settings, window state, assist, update)
    i18n/                text catalog (pt-BR/en-US/es-ES)
    generated/           version.dart (generated by tool/bump_version.ps1)
tool/                    build/version/icon/packaging scripts
tool/linux/              Linux build/packaging scripts (run on Linux)
windows/                 native runner generated by Flutter
linux/                   native runner (GTK) generated by Flutter
assets/                  icon (svg + png) and OFL fonts (Inter, JetBrains Mono)
docs/                    documentation
```

Dependency rule: **frontend → backend** (the backend never imports UI).

## 3. Video engine (media_kit)

Per side:

```dart
final player = Player();
final controller = VideoController(player, configuration:
    const VideoControllerConfiguration(vo: 'libmpv', hwdec: 'auto-copy'));
final native = player.platform as NativePlayer; // advanced access
```

- **Ready to use**: `player.stream.position/duration/playing/completed/volume/rate/error`;
  `setVolume`, `setRate`, `playOrPause`, `seek`.
- **Advanced** (`NativePlayer`): `setProperty`/`getProperty`/`observeProperty`/
  `command`, used for exact seek (`seek <t> absolute+exact`), `container-fps`
  (frame-step leader), `aid` (`has-audio`) and options (`scale`, `framedrop`,
  `interpolation`, `video-sync`, `hwdec`).

`backend/services/playback_bridge.dart` owns all sides and implements: `authority()`,
aligned start, exact `seek` with realignment, frame-step driven by the highest-FPS
side, `resync`, drift correction with hysteresis (≈30 ms deadband, ±3%, ≈700 ms
settle), dual-audio (mutes one side + toast) and `ended` detection. It also samples
per-side buffer seconds/bytes and video size/codec for the HUD and the statistics
overlay.

## 4. Multi-video layout engine

`backend/models/models.dart` defines the layout model:

- `Side { a, b, c, d }` — up to four videos (labels A–D).
- `SplitLayout` — the valid layouts per count
  (`SplitLayout.forViewCount(n)`, `SplitLayout.defaultFor(n)`):
  - **1**: none (full area).
  - **2**: `sideBySide`, `stacked` (default `sideBySide`).
  - **3**: `columns3`, `rows3`, `topPairBottomSingle`, `topSingleBottomPair`,
    `singleLeftPairRight`, `pairLeftSingleRight` (default `columns3`).
  - **4**: `grid2x2`, `columns4`, `rows4`, `topTripleBottomSingle`,
    `topSingleBottomTriple`, `singleLeftTripleRight`, `tripleLeftSingleRight`
    (default `grid2x2`).
- `LayoutSpec` / `LayoutCell` describe each layout as a grid (`cols`×`rows`) with
  cells that may span multiple `colSpan`/`rowSpan` tracks (e.g. `grid2x2` is 2×2,
  `topPairBottomSingle` is 2×2 with the bottom cell spanning both columns).
- `resolveLayoutCells(...)` turns a layout + viewport size into a `CellRect` per
  side; for 2-video layouts it honours the `splitPercent` (draggable divider).
- `frameOrder` + `viewRotation` decide which video occupies which cell, so
  **"rotate positions"** just permutes the order; **"rotate video"** rotates the
  image itself 90°.

`capture_service.dart` reuses the same geometry (`layoutSpec` + `resolveLayoutCells`)
to compose the PNG so the saved image matches what is on screen, including spans.

## 5. UI

- **Wipe**: `Stack` of `Video` widgets; the top one is clipped with `ClipRect` +
  `CustomClipper<Rect>`.
- **Columns / layouts**: `Row`/`Column` with `Expanded(flex:)`, driven by
  `resolveLayoutCells`.
- **Blink**: `Timer.periodic(intervalMs)` alternates the visible side; a large A/B
  letter (top/center/bottom) and a control in the button's hover popover.
- **Divider**: `GestureDetector` + `CustomPaint` (click-arm / drag / double-click to
  recenter).
- **PNG capture**: `Player.screenshot()` per side, then composed in Dart (platform
  video textures cannot be captured with a `RepaintBoundary`).
- **Drag & drop**: `desktop_drop`. **Window / fullscreen**: `window_manager`.
- The **settings modal** is draggable and has no barrier (the app stays interactive
  and videos keep playing behind it); it closes with the X or `Esc`.

## 6. i18n

- `backend/i18n/strings.dart` — catalog (`Strings.ptBr/enUs/esEs`) + `AppLanguage`.
- `stringsProvider` derives from `settings.language`; changing the language in
  Settings updates the whole app immediately. `MaterialApp` uses `locale` +
  `flutter_localizations`.
- The selector shows **drawn flags** (`frontend/widgets/flag.dart`; Windows does not
  render flag emoji) plus the code (`pt-BR`, `en-US`, `es-ES`).

## 7. Update check

- `backend/services/update_service.dart` queries the public GitHub Releases API
  (`.../releases/latest`) with `dart:io` `HttpClient` (8 s timeout), compares the tag
  to `appVersion` with a small semver comparison and returns
  `upToDate` / `available` / `failed`. It never downloads or installs; `openExternalUrl`
  opens the release page with the OS handler (`cmd /c start`, `open`, `xdg-open`).
- `backend/state/update.dart` exposes it as an `AsyncNotifierProvider`; the check runs
  in the background on startup (`AppShell.initState`). The Settings modal renders the
  current version, the status and the actions; the settings button shows a badge when
  an update is available.

## 8. Persistence

- Settings are **portable**: `backend/state/portable_store.dart` writes JSON next to
  the executable (release) or the runner (debug). `SettingsStore` keeps
  `settings.json`; window bounds live in the same file under the `window` key.
  Deleting the app folder therefore removes the settings too — nothing is left in
  AppData / SharedPreferences.
- `window_state.dart` stores normal window bounds (never while minimized —
  `-32000,-32000` on Windows — or fullscreen), validates them as plausible and
  restores them on startup when **Remember app size and position** is enabled.

## 10. Versioning and build

Beta version `0.0.x`, bumped automatically on every build.

- `tool/bump_version.ps1` — increments `PATCH`/`BUILD` in `pubspec.yaml` and
  generates `lib/backend/generated/version.dart` (`appVersion`, `appCommit`).
  `-NoBump` only regenerates the Dart file.
- `tool/build.ps1` / `tool/dev.ps1` / `tool/run.ps1` — bump + `flutter build` /
  `flutter run`.
- The version appears on the top bar as `v0.0.x (commit)`.

## 11. Packaging

`tool/package.ps1` writes to `dist/`, following
`video-splitview-v<ver>-<system>-<arch>` (e.g. `-v0.0.47-windows-x64`):

| Artifact | Description |
| --- | --- |
| `video-splitview-v<ver>-windows-x64-setup.exe` | Installer (Inno Setup). Requires `ISCC.exe`. |
| `video-splitview-v<ver>-windows-x64-portable.zip` | Self-contained portable (exe + DLLs + data + `READ-ME.txt`). |
| `video-splitview-v<ver>-<distro>-x64.deb/.rpm` | Native installer (distro = `ubuntu`, `fedora`, …). |
| `video-splitview-v<ver>-linux-x64.AppImage` | Portable AppImage (distro-independent). |

Flutter does **not** produce an installer by itself; the `setup.exe` needs Inno
Setup:

```powershell
winget install --id JRSoftware.InnoSetup -e
```

Without it, `package.ps1` still builds the ZIP and warns.

On Linux, `tool/linux/build.sh` compiles the release and calls the matching packager:

- `package_deb.sh` — `Depends: libgtk-3-0 | libgtk-3-0t64, libmpv2 | libmpv1,
  libepoxy0, libglib2.0-0 | libglib2.0-0t64`.
- `package_rpm.sh` — `Requires: gtk3, mpv-libs, libepoxy`.
- `package_appimage.sh` — bundles libmpv and its dependency closure (excluding
  host-provided graphics/audio libs), so GTK3/X11 must exist on the host.

`_common.sh` shares helpers (distro/arch detection, desktop entry, RPATH
normalization with `patchelf`, libmpv dependency collection, cached `appimagetool`).

## 12. Dev prerequisites

See the "Clone and build locally" section of the [README](../README.md) for the
step-by-step instructions. In short:

- **Windows**: Flutter SDK (stable, Windows desktop enabled), Visual Studio 2022 with
  *Desktop development with C++*, Windows Developer Mode, Git.
- **Linux**: WSL2 with a distro (or native Linux), `sudo`, Git/curl; the toolchain is
  installed by `tool/linux/setup_env.sh` (apt/dnf deps, Flutter SDK, appimagetool).

## 13. Notes

- `media_kit` (C++ + `libmpv-2.dll` on Windows) and `super_native_extensions`
  (native, via Cargokit) compile native plugin code during the build. This is
  transparent and is not our code.
- The AppImage needs GTK3/X11 on the host; the `.deb`/`.rpm` depend on the system
  `libmpv`.
